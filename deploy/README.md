# استقرار روی crm.parsian-ppm.com

این پوشه تنظیمات پیشنهادی است؛ هنوز روی سرور مقصد نصب یا فعال نشده است.

## پیش‌نیازهای دسترسی

- IP سرور مقصد، سیستم‌عامل، نام کاربر SSH و دسترسی نصب سرویس.
- ورود امن SSH از محیط مجری؛ کلید خصوصی و گذرواژه در چت نوشته نشوند.
- مشخص‌شدن پنل مدیریت DNS دامنه؛ در صورت استفاده از API آروان، کلید با دسترسی متناسب باید از مسیر امن محیط تنظیم شود.
- اگر سرور جدید لازم است، منطقه، ظرفیت و هزینه پیش از ساخت سرویس پولی مشخص شود.

## ترتیب نصب پس از فراهم‌شدن دسترسی

۱. سرویس‌ها، وب‌سرور، پورت‌ها و پیکربندی فعلی سایت اصلی روی مقصد بررسی و از تنظیماتی که تغییر خواهند کرد پشتیبان گرفته شود.

۲. Node.js 24 یا بالاتر نصب و کاربر سیستمی `parsian-crm` ایجاد شود. کد نسخه آزمایش‌شده از شاخه `release/parsian-crm-v2` در یک پوشه release نصب شود؛ مسیر `/opt/parsian-crm/current` به release فعال اشاره کند. فایل‌های کد برای کاربر سرویس خواندنی باشند.

۳. مسیر `/var/lib/parsian-crm` با مالکیت کاربر سرویس و مجوز 0700 ایجاد شود. دیتابیس مشتری خارج از پوشه کد، در همین مسیر نگهداری شود. اطلاعاتی که فقط روی لپ‌تاپ کاربر است در این محیط وجود ندارد؛ انتقال آن پس از خاموش‌کردن اپ مبدا و تهیه بکاپ، از مسیر امن انجام شود.

۴. فایل `production.env.example` به `/etc/parsian-crm/production.env` منتقل و سرویس systemd نصب شود. قبل از استفاده، مسیر `/usr/bin/node` با محل واقعی نصب Node تطبیق داده شود. برای سروری که اپ‌های دیگری دارد ابتدا آزادبودن پورت 3000 بررسی شود.

۵. سرویس فقط روی loopback گوش کند. پیش از فعال‌کردن دسترسی وب، دیتابیس دارای مدیر معتبر وارد شود یا حساب مدیر از طریق درخواست محلی امن ساخته شود؛ مسیر راه‌اندازی اولیه بدون حساب مدیر در اینترنت باز نشود.

۶. رکورد A فقط برای `crm.parsian-ppm.com` به IP مقصد تنظیم شود. رکوردهای دامنه اصلی، وب‌سایت و ایمیل حفظ شوند. اگر CDN فعال است، روش گواهی مبدا و تنظیم HTTPS آن با معماری واقعی تطبیق داده شود.

۷. virtual host مختص CRM به وب‌سرور موجود افزوده شود. فایل Nginx این پوشه فقط برای میزبان دارای Nginx مناسب است؛ برای Apache یا هاست اشتراکی باید با امکانات همان سرویس تطبیق داده شود. پس از بررسی پیکربندی، reload انجام شود.

۸. HTTPS و تمدید خودکار گواهی تنظیم، HTTP به HTTPS هدایت و سپس ورود، چهار نقش و ثبت یک فرایند آزمایشی بررسی شوند. `COOKIE_SECURE=1` برای اجرای HTTPS است؛ این فایل به‌تنهایی HTTPS را فعال نمی‌کند.

۹. پشتیبان دوره‌ای دیتابیس با SQLite backup API و یک کپی خارج از سرور تهیه شود. در هر ارتقا ابتدا از دیتابیس بکاپ گرفته و کد release جدید آزمایش شود. هنگام بازگشت کد، سازگاری ساختار دیتابیس بررسی شود؛ داده جدید با بکاپ قدیمی جایگزین نشود.

تنظیمات DNS، گواهی و نصب روی سرور هنوز انجام نشده‌اند. تنظیمات این پوشه شامل اطلاعات ورود یا کلید نیستند.

## نصب از کنسول سرور

`install-domain.sh` برای نصب اولیه روی Ubuntu 22.04/24.04/26.04 یا Debian 12/13 با systemd آماده شده است. این اسکریپت هنوز روی سرور مقصد اجرا نشده است. دستور `bash -n` و آزمون‌های read-only پیش‌شرط‌ها در محیط توسعه اجرا می‌شوند؛ این‌ها جای آزمون روی سرور واقعی را نمی‌گیرند.

نصاب قبل از نصب، DNS مستقیم به IP، پورت‌های اشغال و تداخل نصب قبلی را بررسی می‌کند. در صورت وجود وب‌سرور دیگری مثل Apache یا تنظیم قبلی همین زیردامنه، متوقف می‌شود تا پیکربندی موجود بررسی شود. Node.js جدا از Node سایت‌های دیگر نصب و checksum فایل رسمی کنترل می‌شود. نسخه کسب‌وکاری برنامه به commit آزمایش‌شده `8bf5a4c60f9ff98648182e2d912f3a8d57c82495` مقید است.

این روش نیازمند اجرای یک فرمان از طرف دارنده دسترسی root/sudo در کنسول آروان است. رکورد Cloudflare باید برای راه‌اندازی اولیه DNS-only باشد و پورت‌های 80 و 443 در فایروال ابری باز باشند. نصاب، شبکه آروان یا DNS Cloudflare را تغییر نمی‌دهد و سرویس پولی جدیدی نمی‌سازد.

نصاب از تنظیمات قبلی Nginx و دیتابیس موجود در مسیر اختصاصی CRM بکاپ می‌گیرد، کد را در پوشه release نصب می‌کند، سرویس دائمی و میزبان اختصاصی Nginx را می‌سازد و گواهی HTTPS می‌گیرد. پیش از انتشار، در صورت خالی‌بودن دیتابیس، از اپراتور نام و رمز جدید مدیر CRM را می‌پرسد؛ رمز در فایل تنظیمات ثبت نمی‌شود. کلید خصوصی یا گذرواژه پنل آروان در این اسکریپت وجود ندارد.

اطلاعاتی که فقط روی لپ‌تاپ ثبت شده‌اند باید جداگانه از مسیر امن به سرور منتقل شوند؛ نصاب به آن لپ‌تاپ دسترسی ندارد. اپراتور باید پیام موفقیت و دسترسی واقعی از دستگاه خودش را بررسی کند. در صورت خطا، خروجی خطا بررسی شود و نصاب بی‌تغییر تکرار نشود.
