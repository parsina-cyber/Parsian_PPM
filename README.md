# پارسیان CRM — نسخه ۲

اپ مدیریت مشتریان و پیگیری تیم فروش با رابط فارسی، راست‌به‌چپ، تم تیره، تقویم شمسی و پایگاه‌داده SQLite.

## اجرا

Node.js نسخه ۲۴ یا جدیدتر لازم است. هیچ وابستگی npm برای اجرای اپ وجود ندارد.

روی ویندوز، کل ZIP را استخراج و روی `RUN-WINDOWS.cmd` دوبار کلیک کنید. این فایل پیش‌نیاز را بررسی، در صورت نیاز Node.js رسمی را با winget نصب و مرورگر را باز می‌کند. راهنمای بیشتر در [LOCAL-WINDOWS.md](LOCAL-WINDOWS.md) است.

اجرای دستی از داخل پوشه پروژه:

```sh
npm start
```

برای توسعه:

```sh
npm run dev
```

در اولین مراجعه حساب **مدیر فروش** ساخته می‌شود. از «اعضای تیم» کارشناس فروش تعریف کنید تا ثبت مشتری ممکن شود؛ منشی و کارشناس فنی هم از همان بخش اضافه می‌شوند. اپ حساب یا رمز پیش‌فرض ندارد.

## چهار نقش و دسترسی‌ها

| نقش | دسترسی |
| --- | --- |
| منشی | فقط ثبت اولیه و تخصیص مشتری به یک کارشناس فروش؛ بدون مشاهده پرونده‌ها یا انجام مراحل بعدی |
| کارشناس فروش | ثبت اولیه مشتری و انجام مراحل پرونده‌های تخصیص‌یافته به خودش تا پایان |
| مدیر فروش | مشاهده و انجام مراحل تمام مشتریان، فیلتر بر اساس کارشناس و مدیریت اعضای تیم |
| کارشناس فنی | مشاهده و پاسخ فقط به تیکت فنی فعالِ تخصیص‌یافته به خودش |

دسترسی‌ها در API نیز کنترل می‌شوند. مسئول فروش در لحظه ثبت اولیه تعیین می‌شود و حتی مدیر فروش نمی‌تواند بعداً آن را تغییر دهد. فروش می‌تواند هنگام ثبت مشتری جدید، او را به یک کارشناس فروش دیگر تخصیص دهد؛ سپس فقط مسئول تعیین‌شده و مدیر به پرونده دسترسی دارند.

کارشناس فنی، توضیحات ثبت اولیه، یادداشت‌های فروش و قیمت‌های اعلامی را دریافت نمی‌کند و به تاریخچه فروش دسترسی ندارد. اطلاعات تماس، موضوع تیکت، محصول و مشخصات فنی دستگاه برای پاسخ در اختیارش است. بعد از پاسخ، پرونده از کارتابل فنی خارج می‌شود و به همان مسئول فروش برمی‌گردد.

## فرایند و فرم‌ها

۱. **ثبت اولیه:** فقط نام و نام خانوادگی، شماره مشتری، توضیحات و انتخاب کارشناس فروش. کد یکتا، تاریخ ثبت و کار تماس اولیه خودکار ایجاد می‌شوند. شماره تکراری پذیرفته نمی‌شود.

۲. **تماس اولیه و نیازسنجی:** ثبت نتیجه و تاریخ واقعی تماس، شماره و نوع پیام‌رسان، آدرس، سمت، حوزه کاری، محصول موردنظر برای تولید، نحوه آشنایی، آمادگی و زمان احتمالی خرید. هر دستگاه ردیفی مستقل با نام/مدل، تناژ، ویژگی فنی و قیمت اعلامی همراه واحد پول دارد. تا ۳۰ دستگاه قابل ثبت است. این فرم فقط **یک فیلد توضیحات تماس** دارد و موعد تماس بعدی را می‌گیرد. تماس بی‌پاسخ بدون نیاز به اطلاعات کامل نیازسنجی ثبت و با موعد جدید باز می‌ماند.

۳. **ارسال کاتالوگ و فیلم معرفی کارخانه:** یک مرحله واحد برای ارسال هر دو مورد در روز تماس اولیه است. ثبت انجام این مرحله، تأیید ارسال هر دو توسط کارشناس است. اعتمادسازی کار جداگانه‌ای برای دو روز تقویمی بعد است.

۴. **پیگیری فروش:** چهار تماس مؤثر پس از تماس اولیه. هر تماس توضیحات و موعد بعدی دارد؛ تماس بی‌پاسخ در شمارش چهار تماس نیست. بعد از چهار تماس، پرونده به پیگیری بلندمدت می‌رود. برای هر مشتری فقط یک پیگیری فروش فعال، چه باز و چه موقتاً متوقف، در پایگاه‌داده مجاز است.

۵. **مشاوره فنی:** فروش هنگام ارجاع، کارشناس فنی و موضوع درخواست را انتخاب می‌کند. کارهای فروش موقتاً متوقف می‌شوند. فنی فقط تاریخ واقعی و یک پاسخ ثبت می‌کند؛ فرم درخواست و پاسخ، فیلد اقدام بعدی ندارند. پس از پاسخ، مرحله و کارهای فروش قبلی با همان مسئول و موعدهای قبلی ادامه پیدا می‌کنند.

۶. **بازدید و جلسه قرارداد:** تاریخ و ساعت خود جلسه و توضیحات در زمان برنامه‌ریزی ثبت می‌شوند. ثبت نتیجه جلسه شامل تاریخ واقعی، نتیجه و توضیحات است و موعد اقدام بعدی ندارد. لغو یا عدم حضور هم قابل ثبت است.

۷. **پیش‌فاکتور:** وضعیت، شماره، تاریخ ارسال و توضیحات؛ بدون فیلد اقدام بعدی. بارگذاری فایل پیاده‌سازی نشده است.

۸. **بازگشت به پیگیری:** پس از نتیجه بازدید/جلسه یا ثبت پیش‌فاکتور، اگر کار فروش فعالی موجود باشد همان ادامه پیدا می‌کند. در نبود کار اصلی فعال، یک پیگیری برای روز ثبت ساخته می‌شود؛ پیگیری موازی جدید ساخته نمی‌شود. پاسخ فنی، کار متوقف‌شده قبلی را دوباره فعال می‌کند.

۹. **پایان و بازگشایی:** بستن پرونده با نتیجه و علت، همه کارهای باز یا متوقف را لغو می‌کند. بازگشایی با علت و موعد، یک پیگیری فعال ایجاد می‌کند.

## نگهداری اطلاعات و ارتقا از نسخه قبل

پیش از ارتقا، سرور قبلی را با `Ctrl+C` متوقف و کل پوشه اپ و پوشه `data` را جداگانه نگه دارید. فایل‌های نسخه جدید، از جمله **domain.js**، باید کنار `server.js` قرار بگیرند. فایل‌های کد جدید را جایگزین کنید و پوشه داده قبلی را حفظ کنید. فایل ZIP توزیع شامل دیتابیس یا حساب‌های قبلی نیست.

در اولین اجرای نسخه جدید روی دیتابیس قبلی:

- قبل از تغییر داده‌های قدیمی، یک پشتیبان سازگار با SQLite با نام `crm.sqlite.before-v2-…bak` کنار دیتابیس ساخته می‌شود.
- نقش قدیمی `admin` به `manager` تبدیل می‌شود؛ حساب‌ها و رمزها حفظ می‌شوند.
- مشتری، تاریخچه و شناسه مسئول فروش باقی می‌مانند. مسئولان قدیمی که مدیر بوده‌اند، همچنان می‌توانند پرونده خود را مدیریت کنند؛ تخصیص مشتری جدید به کارشناس فروش انجام می‌شود.
- یادداشت‌ها و تناژ قدیمی حفظ می‌شوند؛ اطلاعات قدیمی دستگاه به ردیف دستگاه منتقل می‌شود و هنگام نیازسنجی جدید می‌توان مشخصات و قیمتش را کامل کرد.
- کاتالوگ و فیلمِ باز به یک کار تبدیل می‌شوند؛ ردیف‌های تاریخی حذف نمی‌شوند.
- پیگیری‌های موازی موجود یکپارچه می‌شوند؛ نزدیک‌ترین موعد باقی می‌ماند و ردیف‌های اضافه به وضعیت لغوشده می‌روند.
- تبدیل فقط یک بار انجام می‌شود. راه‌اندازی مجدد، اطلاعات را دوباره تبدیل نمی‌کند.

دیتابیس اصلی در `data/crm.sqlite` است. برای پشتیبان‌گیری دستی، سرور را متوقف و کل پوشه `data` را کپی کنید؛ هنگام فعالیت سرور از SQLite backup API استفاده کنید تا داده‌های WAL جا نماند. نسخه کپی روی لپ‌تاپ دیگر به‌صورت خودکار همگام نمی‌شود.

## تنظیمات اجرا

| متغیر | پیش‌فرض | کاربرد |
| --- | --- | --- |
| `PORT` | `3000` | پورت سرور |
| `HOST` | `0.0.0.0` | آدرس شنود؛ فایل اجرای ویندوز آن را برای اجرای محلی به `127.0.0.1` محدود می‌کند |
| `DB_PATH` | `data/crm.sqlite` کنار سرور | مسیر پایگاه‌داده |
| `COOKIE_SECURE` | غیرفعال | برای استقرار HTTPS مقدار `1` بدهید |

تاریخ‌ها در پایگاه‌داده استاندارد و در رابط و CSV شمسی هستند. مبنای روز و ساعت `Asia/Tehran` است. رمزها با scrypt هش می‌شوند و نشست‌ها کوکی HttpOnly دارند.

یادآوری‌ها داخل اپ هستند؛ ارسال خودکار پیامک، پیام‌رسان، ایمیل و بازیابی رمز پیاده‌سازی نشده‌اند. ثبت ارسال محتوا توسط کارشناس انجام می‌شود.

## آزمون‌ها

```sh
npm test
```

پنج آزمون یکپارچه با سرور و دیتابیس موقت، چهار نقش، ثابت‌ماندن مسئول، قیمت مستقل چند دستگاه، تک‌توضیح نیازسنجی، ارسال ادغام‌شده، ارجاع و بازگشت فنی، حذف موعد بعدی از مراحل مربوط، پیگیری یکتا، بستن و بازگشایی، ذخیره پس از راه‌اندازی مجدد و ارتقای دیتابیس قدیمی را بررسی می‌کنند. آزمون‌ها داده واقعی را تغییر نمی‌دهند و به شبکه loopback نیاز دارند.

آزمون اختیاری مرورگر با Playwright نصب‌شده در محیط آزمون:

```sh
npm run test:browser
```

متغیر `PLAYWRIGHT_MODULE` می‌تواند مسیر ماژول نصب‌شده Playwright و `CHROMIUM_PATH` مسیر Chromium را مشخص کند. با `CRM_SCREENSHOT_DIR` می‌توان تصاویر آزمون را در یک پوشه ذخیره کرد. این ابزارها فقط برای آزمون مرورگرند و برای اجرای اپ لازم نیستند.
